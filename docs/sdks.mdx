Official SDKs wrap every endpoint in these docs except the [Admin endpoints](./admin/overview.md). Using one saves you from dealing with the API's quirks yourself:

- **Errors are exceptions.** Most endpoints answer a failure with HTTP 200 and a sentence such as `List does not exist` (see [Authentication](./authentication.md#responses-and-errors)). The SDKs recognise these messages and throw a typed error with a stable code, such as `list_not_found`, so you never have to match strings.
- **Results are parsed.** Plain-text and JSON responses become native values, and an empty result (`No lists found`) is an empty list rather than an error.
- **Reads are retried, writes never are.** A read that hits a dropped connection or a 429/502/503/504 is retried, honouring `Retry-After`. Sends and other writes are not, because the API has no idempotency keys and a retried send could go out twice.
- **Request quirks are handled for you:** the form vs JSON bodies, the `boolean=true` flag on subscribe, comma-joined id lists, and the 250-recipient limit on [Send email](./emails/send.md), which is checked before anything is sent.

## Install

<Tabs groupId="sdk-language">
<TabItem value="ts" label="TypeScript" default>

```bash
npm install @skrybe/sdk
```

Node.js 18 or newer. No runtime dependencies, with ESM and CommonJS builds.

</TabItem>
<TabItem value="php" label="PHP">

```bash
composer require skrybe/sdk-php
```

PHP 8.2.35, 8.3.36, 8.4.27, 8.5.12 or newer within those branches. Uses Guzzle 7.

</TabItem>
<TabItem value="py" label="Python">

```bash
pip install skrybe-sdk
```

Python 3.10 or newer. Imports as `skrybe`; uses `requests` and certifi 2026.10.19 or newer.

</TabItem>
<TabItem value="java" label="Java">

Add JitPack as a repository, then the dependency. Maven:

```xml
<repositories>
    <repository>
        <id>jitpack.io</id>
        <url>https://jitpack.io</url>
    </repository>
</repositories>

<dependency>
    <groupId>com.github.skry-be</groupId>
    <artifactId>skrybe-sdk-java</artifactId>
    <version>v2.0.0</version>
</dependency>
```

Gradle:

```groovy
repositories { maven { url 'https://jitpack.io' } }
dependencies { implementation 'com.github.skry-be:skrybe-sdk-java:v2.0.0' }
```

Java 11 or newer. Uses the JDK's `HttpClient` and Jackson.

</TabItem>
</Tabs>

## Quick start

<Tabs groupId="sdk-language">
<TabItem value="ts" label="TypeScript" default>

```ts
import { Skrybe } from '@skrybe/sdk'

const skrybe = new Skrybe({ apiKey: process.env.SKRYBE_API_KEY! })

await skrybe.emails.sendTransactional({
  toEmail: 'ada@example.com',
  subject: 'Your code',
  plainBody: 'Your code is 123456',
})

const lists = await skrybe.lists.list() // [{ id, name }, ...]
```

</TabItem>

```

</TabItem>

```

</TabItem>
<TabItem value="java" label="Java">

```java

        .toEmail("ada@example.com")
        .subject("Your code")
        .plainBody("Your code is 123456")
        .build());

```

</TabItem>

Each client also takes a base URL (default `https://dashboard.skry.be`), a timeout and a retry count. See each SDK's README for all of the options.

## Errors

Every failure is one error type with a subclass for its kind:

| Kind | TypeScript and Python | PHP and Java | When |
|---|---|---|---|
| Authentication | `AuthenticationError` | `AuthenticationException` | The key is missing or wrong (`invalid_api_key`). |
| Invalid request | `InvalidRequestError` | `InvalidRequestException` | The request is wrong and will fail again unchanged, e.g. `list_id_invalid`, `invalid_schedule`. |
| Rate limit | `RateLimitError` | `RateLimitException` | A quota or rate limit was hit: `quota_exceeded`, `rate_limited`. |
| Connection | `ConnectionError` | `ConnectionException` | The API could not be reached (`network_error`) or did not answer in time (`timeout`). |
| API | `ApiError` | `ApiException` | Anything else the API refused, e.g. `campaign_not_found`, `campaign_not_draft`, `domain_not_verified`. |

They all extend `SkrybeError` (TypeScript and Python) or `SkrybeException` (PHP and Java), and carry a stable code, a hint about what to do when one is known, the HTTP status and the raw response body.

<Tabs groupId="sdk-language">
<TabItem value="ts" label="TypeScript" default>

```ts
import { RateLimitError, SkrybeError } from '@skrybe/sdk'

try {
  await skrybe.campaigns.send(id, { listIds: [listId] })
} catch (err) {
  if (err instanceof RateLimitError) {
    // quota_exceeded or rate_limited
  } else if (err instanceof SkrybeError && err.code === 'campaign_not_draft') {
    // already sent
  } else {
    throw err
  }
}
```

</TabItem>
<TabItem value="php" label="PHP">

```php
use Skrybe\Exception\ApiException;
use Skrybe\Exception\RateLimitException;

try {
    $skrybe->campaigns->send($id, ['listIds' => [$listId]]);
} catch (RateLimitException $e) {
    // quota_exceeded or rate_limited
} catch (ApiException $e) {
    if ($e->getErrorCode() === 'campaign_not_draft') {
        // already sent
    }
}
```

</TabItem>
<TabItem value="py" label="Python">

```python
from skrybe import RateLimitError, SkrybeError

try:
    skrybe.campaigns.send(campaign_id, list_ids=[list_id])
except RateLimitError:
    ...  # quota_exceeded or rate_limited
except SkrybeError as err:
    if err.code == "campaign_not_draft":
        ...  # already sent
    else:
        raise
```

</TabItem>
<TabItem value="java" label="Java">

```java
import com.skrybe.sdk.exception.ApiException;
import com.skrybe.sdk.exception.RateLimitException;

try {
    skrybe.campaigns().send(id, Recipients.builder().listIds(listId).build());
} catch (RateLimitException e) {
    // quota_exceeded or rate_limited
} catch (ApiException e) {
    if (e.getErrorCode().equals("campaign_not_draft")) {
        // already sent
    }
}
```

The exceptions are unchecked.

## Upgrading from 1.x

2.0 of each SDK is a rewrite (Python's previous release was 0.1.0, and its import package is now `skrybe` rather than `skrybe_sdk`; Java's Maven groupId is now `com.github.skry-be`, as JitPack serves it): methods moved onto resources (`skrybe.campaigns.create()` instead of `sdk.createCampaign()`), results are parsed, and failures throw instead of being returned. Each SDK's README has a table mapping every 1.x method to its replacement.
